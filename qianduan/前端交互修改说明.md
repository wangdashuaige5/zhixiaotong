## 2. 使用步骤

1. 老师在“校园 → 课堂考勤”选择上课日期（默认今天），页面通过与课表相同的接口加载当天课程；点选对应课程，再选择签到开始时间及截止时间，点击“创建签到并显示二维码”。自动提交该排课的 `timetable.id`，不是 `course_id` 或 `teaching_class_id`，无需记忆或手填 ID。当天无排课时请更换日期，课表未配置则联系管理员。切换日期、重新选课或刷新会清除旧选择/旧二维码，避免展示与表单不符的二维码；已发布任务不会因此在后端撤销。
2. 学生重新登录新版前端，在“校园 → 课堂签到”输入当前账号密码，确认本次登录设备。
3. 点击“相机扫码”，或点击“从相册识别截图”选择一张二维码截图。
4. 核对任务和有效时间，再点击“确认签到”。后端继续检查身份、选课关系、可信设备、签到码和时间窗；迟到结果按后端返回值展示。
5. 教师请保持二维码页面打开。本版不会保存明文签到码到设备持久化存储。

相机扫码使用系统默认扫码界面，相册识别只读取本次选中的图片，不向外部二维码网站上传签到内容或图片。接口依据本机 Scan Kit 声明及[华为默认界面扫码文档](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V13/scan-scanbarcode-V13)。

## 3. 早先前端交互阶段的后端范围（后续修复见总说明）

上述基础交互和二维码签到可使用现有接口完成，无需新增数据库字段或修改后端：

- `GET /api/semesters`、`GET /api/timetables`
- 原有请假、消息、通知和今日课程接口
- `POST /api/devices`
- `POST /api/attendance/tasks`
- `POST /api/attendance/tasks/{id}/sign`

以下属于额外需求，尚未实施：

| 可选扩展 | 需要的后端支持 |
| --- | --- |
| 动态二维码、防止截图转发代签 | 短时动态凭证的签发/刷新与校验；若增加位置或校内网络校验，还需要明确授权及规则。当前静态码不能证明人在教室，截图在有效期内可以被转发。 |
| 教师离开页面后恢复原二维码 | 当前后端仅保存签到码哈希、创建时返回一次明文。需要任务查询以及重新签发/轮换签到码的接口，不能从哈希还原原签到码。 |
| 手机通过 Wi-Fi 连接本机后端 | 当前后端端口仅绑定 `127.0.0.1:8080`，若要开放到受控局域网，需要你批准调整后端部署端口映射和访问范围。也可使用开发工具提供的 USB 端口转发，不改变后端服务。 |

前端 `common/Constants.ets` 地址已改为 `http://127.0.0.1:8080`，用于模拟器或 USB 调试。连接设备后执行 `hdc -t <设备标识> rport tcp:8080 tcp:8080`，让设备访问本机后端；重连或重启设备后应检查转发是否仍有效。其他部署环境需要按实际后端地址配置。

## 5. 在 DevEco Studio 运行与验收

本机构建工具不支持中文项目路径。请将仓库放到纯英文路径，再在 DevEco Studio 中打开 `qianduan`。当前桌面 `zhixiaotong/qianduan` 是本次修改所在的项目；不要打开旧的“小组后端代码-1”目录查找前端。

建议真机依次检查：

1. 学生、老师、管理员、辅导员分别登录，确认“首页/校园/我的”三个 Tab，消息无重复入口且管理/审批/查寝入口保留。
2. 课表切换学期和前后周、首尾周禁用、横向滑动、空周、点击课程详情。
3. 请假开始/结束表单取消和确认；同日结束早于开始被拦截；合法跨日申请正常提交。
4. 教师创建有效排课日期的签到任务；学生扫码确认后成功；相册截图同样可识别。
5. 无二维码截图、多个二维码截图、未开始、过期、重复签到、非本班学生、被撤销的可信设备等场景。
6. 断网失败后重试、扫码界面取消、离开再进入页面，以及长课程名/较小屏幕的实际显示。
