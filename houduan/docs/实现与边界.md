# 实现范围与联调约定

## 与用户附件的关系

需求和详细设计是业务依据，原RAR是分层写法参考，不是完整可启动项目：只有User、UserController、IUserService、UserServiceImpl、UserMapper、UserMapper.xml共6个文件。新工程保留原件供小组对照，重建了Spring Boot3/Java17工程及57个实体、57个Mapper、57个XML。表名、字段及状态编码沿用智校通数据库设计，每表均有id主键，数据库字段使用下画线。

详细设计82个接口全部有对应路由。公共路由以Controller中的映射为准，不以类名是否和设计示例完全同名为准。Map形参是为了延续小组示例风格，实际业务写入白名单字段，SQL值使用参数绑定；不得把前端传来的SQL、表名、排序表达式直接交给Db。

## 关键约定

- 选课记录只在enroll_status=1时占用名额。重复提交返回当前记录；退选后新申请须使用新request_key。历史请求键在outbox_event中保留唯一指纹，清理消息事件时必须保留该幂等索引信息，不能直接清空事件表。
- 优先级筛选支持 `{"order_by":"enroll_time","version":1}` 或 `student_id` 升序，抽签排名先独立持久化，再逐人录取，不在重启后重新抽签。
- 教师只能看到影响授课时段的请假出勤摘要，不返回病情、请假原因或证明材料。相应提示通过教学班消息发送。
- 审批人按有效权限及数据范围选取，排除全校管理角色的自动路由；同范围有多名候选时取用户ID最小者。校方若采用指定负责人，应进一步提供人员指派配置。
- 成绩四舍五入两位；正常总评=平时×平时权重+期末×期末权重。缺考按期末0处理；缓考/免修发布需要校方专项政策，当前明确拒绝直接发布。绩点规则为不及格0，通过后(total_score−50)/10且最高4.00，需学校确认。
- 普通基础维护POST可带id表示更新；高风险操作必须confirmed=true。课程/请假等状态必须走业务接口，不提供任意表CRUD。
- system_config承载分组字典和参数。`file.allowed_extensions`（逗号分隔）与`file.max_mb`（1—100）对上传实时生效；只能收紧服务端支持类型。其他配置为基础资料，不会自动变成新的业务规则。
- CSV最多200行，成绩导入填写当前版本；导出最多20000行，敏感重点关注内容不提供通用导出。用户导入文件含初始密码，应使用独立随机临时密码并通过受控渠道交付，限制原文件访问与保留时间。
- 文件为同步扫描后通过，demo仅执行基础危险特征检查，不是完整杀毒；prod必须ClamAV。100MB文件采用内存处理，需按上传并发配置堆内存与网关限流。
- 模拟续借短时间重复请求（1分钟内）不会重复延长；最多2次，每次30天，逾期或其他读者有效预约时拒绝。正式续借与预约政策以学校系统为准。

## 没有伪装为完成的部分

真实支付、校园卡同步、短信验证、图书外部借还/同步、原生鸿蒙推送和设备系统信任、正式证明签章依赖外部资料。当前仅提供模拟业务或明确503，以及后端受控接口。

通知支持发布时指定草稿或定时生效；当前草稿没有单独的编辑/发布接口，联调时提交完整内容并设置publish_status=1。课程资源采用新增发布；资源撤回、作业草稿编辑及更多批量模板可作为后续管理端迭代。本次不含用户未要求的前端界面。

统计为基础汇总，不等于完整可视化BI；大范围列表部分采用权限过滤后分页，需在真实数据量压测后优化成数据库范围查询。当前CSV批量上限和上传内存处理是实训规模实现，不应直接承诺全校生产吞吐。

P3家长授权、多租户、科研、更多智慧屏场景未纳入首期。正式部署栈、负载SLA、故障恢复和安全扫描仍需在学校环境联调验收，详见正式部署说明及测试报告。
