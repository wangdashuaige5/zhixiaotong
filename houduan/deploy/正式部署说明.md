# 正式联调与上线前检查

本配置用于准备正式环境，**未宣称已经完成生产部署验收**。本次测试未启动真实的MySQL、Redis、RabbitMQ、MinIO、ClamAV或Docker部署栈。镜像版本固定便于复现，上线前需根据学校政策复核支持周期、漏洞公告、镜像签名与摘要，再更新并重测。

## 准备与启动

1. 将 `.env.example` 复制为 `.env`，填写互不相同的强随机密码及至少32字符的JWT和加密密钥，限制文件读取权限。不要上传Git。加密密钥丢失会导致敏感字段无法解密，必须独立备份；不能直接更换后丢弃旧密钥。
2. 将真实域名证书放在 `deploy/certs/fullchain.pem` 和 `deploy/certs/privkey.pem`。不要在程序目录提交真实私钥。默认HTTPS入口8443；按学校网关调整。
3. 执行 `docker compose -f compose.prod.yml up -d --build`。首次ClamAV需要下载病毒库，未准备好时上传应返回503，不放行未扫描文件。
4. 应用启动完成后Flyway创建表。prod不会自动创建公开演示账号；在本机运行 `python3 tools/bootstrap_admin.py`，按提示生成一次性的管理员初始化SQL。仅在全新空业务库中由数据库负责人审核后执行 `deploy/bootstrap-admin.sql`。密码通过交互输入，不应出现在命令历史。
5. 初始化账号为 `bootstrap_admin`，密码为自己刚输入的值。该账号用于建立组织、人员并授权，应在创建和验证接管管理员后停用。它持有敏感授权委派能力，不能作为普通演示账号或共享账号。
6. 调用组织、用户、角色、辅导员关联、学期、课程、排课和选课批次接口导入真实基础数据。创建用户后通过 `/api/admin/users/{id}/roles` 独立授权；自定义范围角色需要org_id。学生必须先有班级。

不要把demo库直接作为正式库，不要执行历史5条示例SQL覆盖业务库。旧系统数据接入应建立独立迁移、校验和回滚方案；禁止直接开启Flyway baseline绕过结构差异。

## 依赖与网络

- 仅Nginx对外提供HTTPS；数据库、Redis、RabbitMQ、对象存储和ClamAV在容器网络中，不发布到公网。
- MinIO初始化为私有桶，客户端必须经后端授权下载；示例使用存储管理账号便于联调。上线应改成仅限campus-private桶的专用最小权限账号。
- MySQL应用账号需要首次Flyway DDL权限。正式运行建议单独迁移账号执行DDL，再为应用账号收紧为业务所需权限。
- 生产会话及限流使用Redis。默认认证源地址取直连地址；Nginx会额外按真实连接IP限流。单网关连接时后端30次/分钟的认证限额会聚合全部用户，应在受信网关校验、转发头白名单和压测后调整RequestLimiter，不能直接相信任意X-Forwarded-For。
- JWT15分钟，刷新会话7天；刷新令牌轮换，复用旧凭证撤销该会话。禁用账号、改密或改角色后令牌版本变化。
- 定时任务从事务事件表投递；RabbitMQ确认后标记发送完成，消费者失败进入campus.failed死信队列。运维需要告警并在排除故障后重放死信；禁止将死信当作成功送达。发送失败最多自动重试6次，之后人工检查outbox_event。
- delivery_status=1在本实现中表示消息已进入站内收件箱，不等于手机系统推送送达。真正HarmonyOS推送需要另外接入校方/华为应用凭据和客户端回执。

## 上线仍需完成

真实校园卡账本、支付签名协议/对账、短信验证、学校图书系统同步、设备原生信任与推送、证明模板与签章。不得把MOCK_PAY作为正式支付渠道。

还需完成依赖与镜像漏洞扫描、HTTPS与密钥管理检查、MySQL真实并发事务测试、500在线用户及100并发选课的负载测试、对象存储和消息故障演练、审计保留期限审批、每日备份与恢复演练。不能以本机H2测试结果替代这些验收。

数据库已在容器参数启用binlog并保留7天，但**没有自动备份或告警平台**。需由运维设置每日一致性全备、binlog异地归档、私有文件备份，记录数据库与文件恢复点，定期在独立库验证恢复；不要在现有业务库直接试验恢复脚本。
